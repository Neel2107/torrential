# torrential (our copy)

This is a private copy of [nexxeln/torrential](https://github.com/nexxeln/torrential), the Rust torrent-streaming engine, with an Expo app for Android and iOS in `mobile/`. The app is for one person, its owner, for now.

## Layout

- `crates/`: the engine (`daemon`, `engine`, `search`, `core`, `tui`, the `torrential` CLI) and `mobile`, which builds the engine as a library the app runs on the phone.
- `web/`: the engine's web app. `web/src/wire.ts` holds the wire types the app imports as `@web/wire`. It is generated: the engine test `the_web_apps_types_are_the_ones_the_engine_writes` rewrites it, so never edit it by hand.
- `mobile/`: the Expo app. Read `mobile/AGENTS.md` before working there. Its docs (`mobile/docs/`) cover the engine API, decisions, the on-phone engine and the council backlog.

## How we work

- **Branch:** commit straight to `mobile` and push after every verified unit. No pull requests. `upstream` is nexxeln's repo; we only read from it.
- **Priorities:** performance first, especially on a mid-range Android phone (Poco F6). Delight and consistency come second.
- **Verify on the real thing.** Typecheck is not proof. Check the change in the app on a device or the simulator, and judge motion and speed only on release builds.
- **Council:** for review, start read-only Codex `gpt-6.2-sol` delegates. Give them the diff, not your conclusions. Verify each finding before you fix it.
- **No comments in code** (the pstack no-comments rule). Name things so the code reads on its own. A doc comment that states a rule the code cannot show is fine.
- **Commits:** a subject of at most 72 characters saying what changed for the person using the app; a body saying why, ending with a `Checked:` line; one change per commit. The full rules, the guard CI runs on every push to `mobile`, and the hooks are in `mobile/AGENTS.md` under Commits.
- **Test titles:** only public-domain or Creative Commons films, such as Night of the Living Dead (tt0063350), Big Buck Bunny, Sintel and Tears of Steel.

## Engine

Build and test from the repo root. On the owner's Mac, Boost and OpenSSL come from Homebrew; `brew --prefix --installed` fails when one is missing instead of exporting an empty path:

```sh
export PATH=/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH
boost=$(brew --prefix --installed boost) && openssl=$(brew --prefix --installed openssl@3) &&
  export BOOST_ROOT=$boost OPENSSL_INCLUDE_DIR=$openssl/include OPENSSL_LIB_DIR=$openssl/lib TORRENTIAL_WEB_DIST=$PWD/web/dist &&
  cargo test --workspace
```

On Linux there is no Homebrew: upstream's `nix develop` shell (`flake.nix`) sets `BOOST_ROOT` and the OpenSSL paths, and then `TORRENTIAL_WEB_DIST=$PWD/web/dist cargo test --workspace`. The phone builds (`mobile/scripts/build-engine.sh`, `build-preview.sh`) run on the Mac only and say so elsewhere.

Homebrew's Rust has no mobile targets; use rustup's. A new engine route needs a test in `crates/daemon/src/daemon/tests/web.rs`, and `wire.ts` gets regenerated by the test above.

## Devices

- **Poco F6 (Android):** reach it over adb. At home use wireless debugging. Away from home use Tailscale: `adb connect <f6 tailnet ip>:5555`. That needs `adb tcpip 5555` run once from home, again after every reboot. Unlock only with `mobile/scripts/f6-unlock.sh`, which types the PIN only when the PIN pad is on screen.
- **Never use `adb shell monkey`.** It sends random input.
- Never tap the F6 blind: take a screenshot or a uiautomator dump before every tap. In scripted loops, tap through `mobile/scripts/f6-tap.sh`, which refuses when torrential isn't in front or the keyboard is open.
- Don't tap the F6 while its owner is using it.
- At night, make no noise: keep media volume at 0, and play no video and fire no haptics.
- **iPhone:** build Release with `xcodebuild … -allowProvisioningUpdates` and install with `xcrun devicectl device install app`. The free Apple ID signing expires after 7 days.
- **iOS simulator:** drive it through the device tools, not `simctl` taps.
